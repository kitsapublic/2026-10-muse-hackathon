# Architecture

The browser calls a local `/v1` service on the same origin. The service installs synthetic bundles, records reviews and immutable jobs in local SQLite, and calls one pinned Eligibility Lab wheel for all calculations. The calculation core uses the Python standard library; HTTP/runtime dependencies are optional.

Muse interprets a criterion into a closed JSON rule proposal, which requires review before execution. For narrative decisions it receives the bounded notes in the declared observation window. Unsupported rules are rejected. A technical failure is separate from a clinical `no`; missing evidence does not establish absence. Patient failure follows any known inclusion failure or exclusion hit. Passing requires every criterion to resolve appropriately; other patients remain unresolved.

Reference mode uses explicitly authored narrative answers. Recorded mode reuses genuine validated responses pinned to evidence, question, date and evaluator settings. Live mode requires a server-side key and an enabled, bounded experiment. Scenario jobs reuse the baseline's narrative answers and recalculate deterministic thresholds without model calls.

The engine source is maintained in its owning repository and distributed here as the same versioned wheel used for verification. The public synthetic bundle is versioned and hashed. This submission excludes private evaluation data, production adapters, databases, credentials and model weights.

Portable recording history is exported and imported by the engine service CLI. The artifact contains only one completed public live baseline under unchanged reference rules: exact requests/responses, accepted-answer lineage, reference reviews and the original result. Import requires a trusted file digest and the identical installed bundle; it revalidates every response and inserts history transactionally into a fresh store. Existing work is refused, and repeated identical imports preserve later local review/run changes. No raw database backup or private rows are distributed. The source evaluator remains historical; a new recorded run uses the current evaluator. Imported source costs are retained separately from new-run costs, with the source ledger disabled and exhausted. The packaged launcher verifies the recording, removes an inherited API key and serves only reference/recorded modes.

The showcase has a guided six-scene view and an Explore view sharing one workflow state. The URL holds bundle, mode, scene, patient and run selections. Navigation is read-only; job submission requires an explicit action, approved rules and live spending consent where applicable. A new baseline clears scenario context. Context-bound loading suppresses stale results, and a late submission response cannot select a job in another bundle or baseline context.

Every guided scene includes a compact Technical note specific to the operation on that screen. The baseline waterfall uses the evaluator’s cumulative counts in protocol order: blue bars show patients passing all criteria evaluated so far, red counts newly excluded patients, and amber counts unresolved patients. Each exclusion is counted at the first failing criterion. The impact view pairs draft and selected scenario waterfalls by criterion ID on a shared scale and highlights changed thresholds. The guided review export contains protocol eligibility evidence and has no site-planning dependency.

The showcase follows Muse's public browser interface with a charcoal background, blue controls and system sans-serif type. Its Muse mark is retained from https://muse.ai/images/landing/brand/muse-logo.svg and appears alongside the model attribution. The application remains identified as Eligibility Lab. The walkthrough explains the workflow in connected sentences; clinical notes, model responses and retained evidence remain unchanged.

Public patient and item-trace endpoints supply dated source evidence and retained request/final-response information. Trace visibility checks both the selected job and any reused source; private sources, credentials, headers and internal reasoning are excluded. Detailed reports load on demand in the execution inspector, while only lightweight jobs are polled. Processing duration is labelled latest worker execution; whole-job elapsed spans creation to completion. Source charges remain separate from new replay charges.

The feasibility export is a downloadable review document, not a task system. It binds baseline/scenario identities, edits, counts, changed patients, unresolved criterion evidence and existing report/matrix/comparison links. Historical aggregate measurements are versioned public evidence, separate from active jobs. The matched comparison consumes only the allowlisted public aggregate artifact produced in fine-tune-models; missing models stay unavailable. Private scoring records and expected answers never enter the browser or runtime archive.

## Site-planning components

Site-planning components and their public evidence remain in the source tree but are not mounted in the guided walkthrough or included in its review export.

The showcase owns `nsclc-site-planning/1`, independent of clinical eligibility calculation. `evidence/site-planning.json` retains the fixed six-campus Kitsa identities, public profiles, matched registry studies, ambiguous exclusions and completeness. Kitsa comparisons were captured in two groups of three, with source digests retained. Registry retrieval covers relevant condition terms and AstraZeneca lead-sponsor studies; it does not claim to measure all site work. The service endpoint is read-only and restricted to those pinned identities and fixed public destinations.

Scores retain intervals for missing facts, uncertain campus matches and incomplete retrieval. Verified lower counts are never presented as complete counts. Recommendations are ordered by the lower score bound, then narrower uncertainty, then site identity. Overlapping intervals do not establish a confident order. An expanded explanation shows each raw input, weighted contribution, source and unresolved question. Collaborators remain separate from lead sponsors.

The regional artifact fixes GLOBOCAN 2024 country-level crude lung-cancer incidence and WPP 2024 medium-variant population projections for 2024. The IARC case counts and country population denominators produce crude annual rates per 100,000; this is incidence, not prevalence. UN single-year population counts determine the fraction within the selected participation age range. The open-ended 100+ group produces a range when an age threshold enters it. These are country context, not hospital catchments or eligible patient estimates.

Public site evidence refreshes only on explicit action. The browser retains successful live responses in session storage, labels each source and timestamp, and preserves earlier evidence when a refresh fails. No patient data accompanies the requests. Settings and selections are stored per baseline and scenario. New scenarios inherit priorities and selections with review required, while a new baseline starts an empty shortlist. Late responses are discarded after context changes. Evidence or policy changes invalidate the review signature. The component’s separate export function requires a reviewed shortlist and includes selected evidence, the full candidate pool scores, policy version, normalized weights and regional dataset identity. It is not called by the guided protocol review export.
